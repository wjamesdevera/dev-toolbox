# Dev Toolbox

A personal collection of **ready-to-use templates, code snippets, project configurations, and technical documentation** for software development.

The goal is simple: **reduce repetitive setup and avoid reinventing the wheel** when starting or working on a project.

## 🛠️ What's Inside

```text
.
├── configs/    # Project and tooling configurations
├── docs/       # Technical documentation and references
├── snippets/   # Reusable code and scripts
└── templates/  # Project and documentation templates
```

### `configs/`

Common configuration files and project setup.

Examples:

- Dockerfiles
- `.gitignore`
- TypeScript configuration
- Linter/formatter configuration
- CI/CD workflows
- Environment configuration examples

### `docs/`

Reusable documentation for planning, designing, and maintaining software projects.

Examples:

- Architecture Decision Records (ADRs)
- System design documents
- API documentation
- Setup and onboarding guides
- Technical specifications

### `snippets/`

Small, reusable pieces of code for common development tasks.

Examples:

- Utility functions
- Shell scripts
- CLI commands
- Common algorithms
- Language-specific patterns

### `templates/`

Starting points for new projects and common development workflows.

Examples:

- `README.md`
- `CONTRIBUTING.md`
- Issue templates
- Pull request templates
- Project documentation

## 🚀 Usage

### 1. Find

Browse the directories or search the repository for what you need.

### 2. Copy

Copy the template, configuration, or snippet into your project.

### 3. Customize

Replace placeholders such as:

```text
<PROJECT_NAME>
<TODO>
<YOUR_VALUE>
```

Then adapt the files to fit the project.

### 4. Improve

If you find yourself repeating the same setup or solution, consider adding it to the toolbox for future projects.

## 📌 Philosophy

This repository is intentionally **practical rather than comprehensive**.

Not every possible configuration, pattern, or tool belongs here. The goal is to keep a collection of things that are:

- Frequently useful
- Easy to reuse
- Simple to understand
- Tested in real projects
- Worth keeping for future work
